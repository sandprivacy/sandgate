The hosted relay

relay.sandgate.dev is what sandgate pair uses when you give it nothing else. It exists so that the first approval takes a QR scan, not a server. Here is exactly what it is.

What it sees

  • Pairing ids — 128-bit random strings
  • Sealed blobs: requests and decisions, AES-256-GCM, keys it never holds
  • Your IP address, like any server you connect to
  • Your phone's push endpoint, so it can wake the app
  • How many devices a quorum needs (the number, nothing else)

What it cannot see or do

  • What is being asked, or what you answered
  • Any 2FA seed, code, password or key
  • Forge an approval — every decision is authenticated to your pairing key
  • Replay a decision onto another request — the request id is bound into the ciphertext
  • Produce a Face ID assertion

The worst a hostile relay can do is drop or delay an answer, and sandgate treats that as a refusal. This is not a promise: it is how the code is written, and the tests in the repo check it on every commit.

What you should know

  • No SLA. It runs on one server, kept up with care and monitored, but if it is down your agents will wait and then refuse — safe, not available. Anything that matters should be able to fall back to your own relay.
  • Limits. 12 requests a minute and 5 unanswered per pairing (against flooding a phone), 240 API calls a minute per address (against abuse). Ordinary use never sees them.
  • Data kept. Push endpoints, until you unpair. Requests, for 30 minutes at most, then dropped. IP addresses are not logged beyond what the web server needs to run; nothing is sold, shared or analysed.
  • Pairing links are one-time claims that expire in ten minutes; the relay hands the sealed secret out once and forgets it.

Run your own instead

Same code, one command, behind any TLS terminator (phones require HTTPS for push):

npm i -g @sandprivacy/sandgate
sandgate relay 8787                       # put Caddy, nginx or a Cloudflare Tunnel in front
export SANDGATE_RELAY=https://relay.your.domain
sandgate pair                             # now pairs against yours, for good

Details, systemd unit, metrics and backup: deploy/README.md.
